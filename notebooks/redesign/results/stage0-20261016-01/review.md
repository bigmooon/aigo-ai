# 단계 0 Critical Review

## 결과

새 커널 전체 실행, nbformat 검증, 추출본 일치, 하네스와 SSE의 11개 테스트 및 4개 하위 사례를 통과했다.
이것은 개발 도구 검증이다. 검색·생성·법률 정확도의 개선은 아직 측정하지 않았다.

## 검토

- 필요성: 노트북 원본과 실행 파일의 불일치를 자동으로 감지한다.
- 단순성: 새 패키지나 서버 없이 표준 라이브러리 함수 3개로 구성했다.
- 안전한 쓰기: 저장소 경계·허용 폴더·소유권·전체 문법을 쓰기 전에 확인한다.
- 평가 공정성: v1 코드·평가셋·서비스를 보존하고 v2 지표 변경을 명시했다.
- 재현성: config.json의 소스 해시에는 미커밋 파일도 포함된다. 실행 시점 commit과 현재 수정 상태를 구분한다.
- 정성 평가: 모델 답변을 생성하지 않았으므로 개선/회귀/미해결 답변 사례와 사람 점수는 N/A다.
- 발견된 제작 문제: Windows stdin 인코딩으로 한글이 손상됐으나 UTF-8로 복구 후 전체 실행했다.
- Git 범위: 로컬 origin/main 대비 선행 10개 commit이 있어 승인 전 PR을 만들지 않았다.

## 한계와 결정

- OS 쓰기 중 오류의 다중 파일 원자성은 제공하지 않는다. Git diff로 복구·검토한다.
- 비밀키 검사는 제한된 패턴 검사다. 사람의 diff 검토를 대체하지 않는다.
- 전체 API 통합 테스트, 상태 전달·SSE 부하·취소 재현, GPU·원격 DB는 실행하지 않았다.
- 하네스 로컬 검증은 완료. 사용자 Git 반영 승인은 pending이며 단계 1 시작도 별도 승인 대상이다.
