# 평가 규약 v2 — 단계 1 구현
01_eval_set.ipynb에 검색 지표·판정 비율·분위수·상황별 비교·split 검사를 구현했다. 아래 기준은 실측 성능이 아니다.
기존 eval_set.json의 원문 14개·변형 31개를 개발용으로 불러온다. 기존 근거 후보는 보존하고 현재 판본·정답 적합성을 사용자와 검토한다. 독립 holdout은 향후 준비한다. [검토 안내](eval/README_v2.md)를 따른다.
숫자는 개선 규모를, 사람이 읽는 사례는 유용성과 오류 원인을 설명한다. 임의의 가중 합계는 만들지 않는다.

## 데이터와 고정 조건

- 주제(category), 답변 방법(answer_method), 현재 지원 상태(support_status)를 구분한다. Q10 정책 질문은 외부 검색 연결 대기이며 범위 밖 거절 정답으로 평가하지 않는다. 도구 연결 전 개별 정책 사실의 정확성은 보류한다. 한계 고지·추가 질문·행동 안내는 아래 확정 종합 정성 척도의 명시된 범위에서 평가한다.

- 현재는 기존 질문 45개를 개발용으로 사용한다. dev 40개·독립 holdout 20개는 향후 확장 목표이며 현재 노트북의 실행 조건이 아니다. 쉬운 질문·구어체·모호함·키워드·특약·복합 조건·답변 불가 포함.
- 같은 상황의 원문·변형은 같은 split. 기존 14항목은 검토 후 dev 또는 범위 밖 회귀 사례로 재사용한다.
- 정답 단위는 문서 판본·조문·절. 청킹을 바꿔도 정답 의미는 유지한다.
- 관련도는 0(무관), 1(도움), 2(핵심). 1 이상을 검색 정답으로 센다.
- 같은 근거의 중복 청크는 최초 위치만 남긴 뒤 top-5를 평가한다. 실제 전달 문맥은 별도로 평가한다.
- 후보들의 검색 결과를 합쳐 블라인드로 관련성을 검토한다. 미판정 문서를 0점으로 가정하지 않는다.
- 질문별 필드: id, scenario_id, split, query, intent, difficulty, expected_behavior, expected_sources, reference_answer, must_include, must_not_include.
- 코퍼스·기준일·모델 revision·프롬프트·환경·출력 상한을 고정하고 한 번에 한 변수만 변경한다.
- 실제 검색 문맥과 정답 문맥을 각각 입력해 검색/생성 실패를 구분한다.
- holdout은 최종 선택 후 평가한다. 결과를 보고 튜닝하면 새 독립 holdout이 필요하다.

## 정량 지표

| 지표 | 쉬운 의미·계산 | 주의 |
|---|---|---|
| Hit@5 | 정답을 하나라도 찾으면 1 | 기존 v1의 recall 표기와 구분 |
| Recall@5 | 찾은 정답 수 / 전체 정답 수 | 정답 2개 중 1개면 0.5 |
| Precision@5 | 상위 5개 관련 근거 수 / 5 | 부족한 자리는 비관련 |
| MRR@5 | 첫 정답 순위의 역수, 없으면 0 | 질문별 값 평균 |
| nDCG@5 | 중요한 근거를 앞에 배치한 정도 | gain=2^관련도-1, discount=log2(rank+1), 전체 gold의 이상 순위로 정규화 |
| Context Precision (AIGO) | 유용한 최종 문맥 단위 / 전달한 단위 | 순위 가중 Ragas 지표와 다르므로 AIGO 정의로 표시 |
| Context Recall | 문맥이 덮는 필수 근거 단위 / 전체 필수 단위 | 필수 근거 라벨을 사람이 검토 |
| Faithfulness | 근거로 지지되는 주장 / 검증 가능 주장 | 단어 중복으로 대체하지 않음 |
| Correctness | 충족한 정답 핵심 조건 / 전체 핵심 조건 | 모순·금지 내용·심각한 오류는 별도 기록하고 채택 차단 |
| Answer Relevance | 질문에 직접 답하는 정도, 1~5 | 아래 채점표 |
| Citation Correctness | 주장을 지지하는 인용 연결 / 전체 인용 연결 | URL 존재만으로 정답 아님 |
| Citation Coverage | 유효 인용이 있는 근거 필요 주장 / 근거 필요 주장 | 인용 누락 확인 |
| Easy Language | 용어·문장·행동 가능성 각 1~5 | 축별·평균 보고, 법적 의미 보존은 별도 필수 조건 |
| 부적절한 확답률 | 확답한 답변 불가 항목 / 답변 불가 항목 | 모호함·근거 부족의 기대 행동 지정 |
| 과도한 거절률 | 불필요하게 거절한 정상 항목 / 정상 항목 | 정상 질문도 함께 평가 |
| P50·P95·첫 토큰 | 보통 지연·느린 지연·첫 출력까지 시간 | 단계별·전체, cold/warm·동시성·표본 수 기록 |
| usage·비용·실패율 | 실제 토큰·GPU 시간/비용·실패 요청/전체 | 문자 수로 토큰 대체 금지, 미제공 null/unknown |

분모 0은 null(N/A)로 표시하고 유효 항목 수를 함께 보고한다. 답변 불가 항목은 검색 Recall 분모에서 제외한다.
정상 질문의 빈 문맥은 Context Precision N/A, 필요한 근거가 있다면 Context Recall 0이다.
인용이 없어 Citation Correctness가 N/A여도 근거 필요 주장이 있으면 Coverage는 0이다.
올바른 답변 유보의 Faithfulness N/A를 만점이나 실패로 치환하지 않는다.
판본 정확성·시행일 유효성·링크 형식·내용 지지는 따로 기록한다. 과거 근거가 없다고 미래 판본을 정답으로 보상하지 않는다.

## 정성 채점

| 축 | 1점 | 3점 | 5점 |
|---|---|---|---|
| 질문 관련성 | 다른 질문에 답함 | 일부 조건만 답함 | 핵심 조건에 직접 답함 |
| 쉬운 용어 | 전문 용어 설명 없음 | 일부만 설명 | 필요한 용어를 일상어로 설명 |
| 문장 명료성 | 길고 모호함 | 읽을 수 있으나 반복 | 짧고 관계가 명확함 |
| 행동 가능성 | 다음 행동 불명확 | 일반적 안내 | 질문에 맞는 확인 사항·행동 |

2·4점은 인접 기준 사이이며 채점 이유를 한 문장으로 남긴다. 단순 용어 질문에 불필요한 행동을 억지로 제안하지 않는다.
법적 의미 왜곡·예외 누락·근거 과장·추가 질문 필요·새 회귀 여부를 별도 기록한다.
잘못된 의무/기한/판본 안내, 근거 없는 단정, 개인정보 노출 등 심각한 오류는 전부 검토한다.
초기 dev 10개로 채점표를 보정한 뒤 버전을 고정한다. 최종 holdout 20개는 사람이 모두 검토한다.
모델명을 숨기고 답변 순서를 섞는다. 한 명이 채점하면 한계를 밝히며 평가자 일치도를 꾸며내지 않는다.
LLM 평가는 보조 수단이다. 사람과의 불일치·이유·최종 판정을 기록한다. 미검토 점수는 null이다.
실험마다 개선 3개·회귀 최대 3개·미해결 3개 사례를 제시하되 부족하면 실제 개수만 제시한다.

## 확정 종합 정성 척도: trust-usability-v1

2026-10-19 사용자 승인으로 고정합니다. 평가명은 **공인중개사 자문을 반영한 Before 정성 평가**입니다. 기준 고정·평가 확정 주체는 사용자이며, 사용자는 공인중개사 자문을 받아 중대한 오류와 평가 확정 여부를 작성했다고 확인했습니다. 자문자의 신원·직접 채점 여부·서명·자문 일자는 추정하지 않습니다. 별도 공인 인증을 의미하지 않습니다.

평가 질문은 **“이 답변을 실제 사용자에게 제공했을 때 얼마나 믿고 활용할 수 있는가?”**입니다.

| 검토 관점 | 확인할 내용 |
|---|---|
| 조건 반영 | 계약 시점·상황을 반영하고, 없는 사실을 가정하지 않았는가 |
| 법률 정확성 | 핵심 결론과 적용 요건이 맞는가 |
| 근거 적합성 | 인용 조문·판례가 해당 주장을 뒷받침하는가 |
| 실무 활용성 | 무엇을 확인하고 어떻게 대응할지 알 수 있는가 |
| 이해하기 쉬움 | 초보자에게 불필요하게 어렵거나 추상적이지 않은가 |

| 점수 | 판단 기준 |
|---|---|
| 1점 | 핵심 결론이 틀리거나, 실질적인 안내가 없음 |
| 2점 | 일부 방향은 맞지만 핵심 판단·대응이 빠짐 |
| 3점 | 핵심 방향은 맞으나 조건·근거·행동 안내 보완이 필요 |
| 4점 | 경미한 수정으로 활용 가능 |
| 5점 | 질문 범위에서 정확하고, 실행 가능하며, 근거가 확인됨 |

- 항목별 가중 합산이 아닌 독립적인 종합 정성 척도입니다. 검색·인용 정확성 등 다른 지표와 합쳐 하나의 점수로 만들지 않습니다. 기존 축별 지표를 이 점수에서 역산하지 않습니다.
- 03_before_review.ipynb의 기존 14개 점수와 의견을 사용자가 확정한 Before 기준선으로 유지합니다. 이 척도 확정을 위해 전체를 다시 채점하거나 별도 축별 점수로 쪼갤 필요는 없습니다. 앞의 dev 10개 보정 절차를 이번 확정의 선행 조건으로 다시 요구하지 않습니다.
- 중대한 오류 의견·평가 확정 여부·보류 범위는 점수와 별도로 기록합니다. 1점에는 위험한 오답과 안내 부족이 모두 포함되므로 점수만으로 중대한 오류를 판정하지 않습니다. ‘우선 수정’을 중대한 오류 유무로 자동 변환하지 않습니다.
- Q01/Q09/Q12의 조건·판본, Q10의 개별 공고 사실과 관련 지표 보류를 유지합니다. Q10 점수는 기존 메모의 한계 고지·질문 구체화·행동 안내 범위이며 정책 사실 정확성 확정점수가 아닙니다.
- After는 동일 질문·척도 버전·평가 범위·보류 처리 기준으로 비교합니다. 판본·사실관계가 확정되어 평가 범위가 바뀌면 양쪽에 동일하게 적용하고 변경을 기록합니다. 결과를 보고 한쪽에만 유리하게 기준을 바꾸지 않습니다.
- 질문별 원점수와 중대한 오류 사례를 우선 보고합니다. 집계할 경우 유효 문항 수·보류 범위·점수 분포를 함께 제시하며 1~5점 차이를 %p로 표현하지 않습니다. 이 개발용 14문항 평가를 독립 holdout 성능으로 표현하지 않습니다.
- 현재 Before는 비블라인드 평가입니다. 후속 블라인드 비교 시 양쪽 답변에 같은 절차를 적용하고 기존 기록과 구분합니다. 확인되지 않은 평가자 수나 평가자 일치도를 만들지 않습니다.

## 판정·불확실성

- 실험 전 주 지표와 성공 기준 고정. 검색 Recall@5, 정렬 nDCG@5, 생성 Correctness 등 목적별 선택.
- 품질 후보: 주 지표 +5%p, 주요 안전성 회귀 없음, 비용·P95 증가 각각 20% 이내.
- 단순화 후보: 품질 저하 2%p 이내를 사전 한계로 두고 주요 안전성 회귀 없이 비용 또는 P95 20% 이상 감소.
- 비용이 미측정이면 비용 조건 통과로 표시하지 않는다. 1~5 척도에 %p를 그대로 적용하지 않는다.
- 질문별 차이·분모·평균을 제공한다. 상황 그룹 단위 paired bootstrap(seed=42, 2,000회)의 percentile 95% 구간을 사용한다. 상황 1개 이하이면 구간은 null이다.
- 변형은 먼저 그룹 안에서 평균내고 그룹에 동일 가중한다. 변형 수를 독립 표본 수로 부풀리지 않는다.
- 지연의 반복·warmup·동시성 조건을 명시한다. 작은 표본의 P95와 불확실한 차이로 우위를 과장하지 않는다.
- 정성 검토에서 심각한 근거 왜곡이 있거나 효과가 불확실하면 채택을 확정하지 않는다.

## 방법론·참고 자료

- [RAGAS 원 논문](https://arxiv.org/abs/2309.15217): 검색 문맥·근거성·답변 품질을 분리하는 배경.
- [Ragas 공식 지표](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/): 개념 참고. 이 단계에서 평가 라이브러리나 LLM judge를 설치하지 않는다.
- [정보검색 평가 교재](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-ranked-retrieval-results-1.html): 순위 평가 배경. AIGO의 K·중복·분모 규칙은 위 표로 고정한다.
- 문제 → 초보자 설명 → 논문/공식 링크·아이디어 → 적용 이유·범위 → 수치·사례·한계 → 결정을 노트북에 기록한다.
- 예: reranker는 검색 후보를 다시 읽고 순서를 정한다. 정답이 후보에 없다면 순서 변경으로 해결할 수 없다.
- 외부 벤치마크 결과는 AIGO 개선 수치가 아니다. 원 논문·공식 구현을 우선하며 최근성과 문제 적합성을 함께 본다.

## 구현과 검토의 경계

- retrieval_metrics: 근거 ID 중복 제거 후 Hit/Recall/Precision/MRR/nDCG@5. 미판정 결과를 0으로 바꾸지 않는다.
- reviewed_rate: 사람 bool 판정의 분자·분모·검토 수. 미검토 항목이 있으면 값은 null이며 검토된 일부만의 평균을 보고하지 않는다.
- percentile: 선형 보간 P50/P95. 실제 요청 지연 수집·토큰 계측은 후속 단계다.
- paired_comparison: 양쪽 값이 있는 질문만 paired 비교하고 제외 수를 함께 보고한다. 서비스 실패는 별도 실패율에 포함한다.
- validate_eval_set: ID·동일 문장·상황 split과 라벨 완결도 검사. 의미 중복·법률 정확성·판본 유효성·인용 내용은 사용자 검토 대상이다.
- blind_review: 답변 순서를 섞고 모델 복원 키를 분리한다. 단독 평가자가 키를 알고 있거나 답변 자체에 모델명이 있으면 블라인드 한계를 기록한다.
- 사람 1~5점은 원점수·축별 평균으로 보고한다. 주장/조건 비율이나 %p 지표와 합쳐 단일 점수를 만들지 않는다.
