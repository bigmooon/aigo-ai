# 결정 기록

## 작업 구조
- 기존 폴더를 유지하고 실제 변경하는 코드만 설명이 있는 노트북에서 작성한다. export 셀의 Python 추출본은 직접 편집하지 않는다.
- 별도 v2 노트북·합성 질문 60개 방식은 사용자 요청으로 기각했다. 01_eval_set.ipynb에서 기존 질문을 사용한다.
- 기각 이유: 기존 사용자 질문보다 새 자료가 중심이 되었고 중복 파일이 늘었다. 당시 검증 이력은 01 노트북에 합쳤다.

## 평가 기준
- 기존 Hit를 Recall로 표기한 결과와 새 지표를 직접 비교하지 않는다. Before도 동일 기준으로 다시 측정해야 한다.
- 정량 수치와 정성 사례를 따로 보고, 미검토 기본 점수·임의 종합 점수를 만들지 않는다.
- 현재 질문은 개발용이며 40/20 분할은 지금 노트북 실행 조건이 아니다. 최종 성능 확인에는 별도 독립 holdout을 준비한다.
- Q03은 실제 주거 문제를 추가로 묻는 dispute/clarify로 사용한다. Q08은 현재 서비스 목적상 out_of_scope로 둔다.
- Q10 policy는 외부 검색으로 답할 대상이다. 도구 연결 대기와 서비스 범위 밖을 구분한다.

## 승인·기록
- 단계 시작, Git 반영, 유료 실행, merge의 승인 경계를 구분한다. PR은 사용자 승인 파일만 포함하고 저장소 템플릿을 따른다.
- 일반 수정의 검증·실패·한계는 해당 노트북에, 현재 상태는 progress.md에 남긴다.
- 코드 검증마다 별도 config/metrics/review/PR 초안을 만드는 방식은 중복이 많아 사용자 요청으로 폐기했다.
- 실제 모델·검색 비교 실험에만 필요한 설정·원시 결과를 별도 보관한다. 판단과 Critical Review는 노트북에 쓴다.
- 검증 기록을 합쳤으며 모델 성능이나 사람 점수를 새로 만들어 넣지 않았다. 과거 전체 파일은 Git 이력에서 확인한다.

## 단계 2: 재구성한 Before
- 운영 DB가 없어 v1-seed 캐시 기반 재구성으로 명시한다. 원본 사본·정규화 문서·복구 입력은 Git 밖에, 최소 manifest와 설명은 03에 둔다.
- 사건번호만 같은 판례를 중복 삭제하지 않는다. 출처·판본을 포함한 ID와 별도 본문 해시를 사용한다. 누락 날짜와 현행 별칭 주소는 미확정으로 남긴다.
- 서비스의 한국어 doc_type 및 실제 source_id 계약에 맞춰 준비 자료만 변환한다. 법령ID는 기존 검색 API 캐시에서 복구하며 서비스 노드의 결함은 수정하지 않는다.
- 기본 실행은 오프라인이다. 실제 모델·색인·답변 수집은 별도 비용 승인 후 실행한다. SSE 문자 길이는 usage로 인정하지 않고 unknown으로 기록한다.
- 2026-10-18 RunPod 준비: 생성 서버를 vLLM 0.31.0 digest로 고정하고 EXAONE/KURE의 공개 commit SHA를 03에 기록했다. 기존 의존성을 보존하기 위해 KURE·Qdrant·노트북은 로컬 CPU, 생성 서버는 RunPod로 분리한다. 서비스 코드와 생성 프롬프트는 유지한다. 이 구성의 latency는 운영 환경 재현값이 아니다.
- Pod 종료는 노트북 timeout과 분리한다. 별도 로컬 프로세스에서 절대 종료 시각에 중지 API를 요청하고 기대 상태를 확인한다. 모의 검증만 완료했으며 실제 과금 종료 보장으로 표현하지 않는다. PC 절전·네트워크 장애·저장료 잔존은 콘솔 확인 대상이다.

- 2026-10-18 후속 승인: KURE·Qdrant·노트북은 Pod CPU와 별도 Python 환경, EXAONE은 기존 vLLM GPU 환경을 사용한다. 원본 입력 manifest는 보존하며 실행 OS·패키지는 runtime에 따로 기록한다. 변경은 배포 위치와 실행 준비에 한정한다.

## 2026-10-19: Before 정성 기준선 확정
사용자가 제시한 신뢰·활용 가능성 1~5점 척도를 trust-usability-v1로 고정했다. 공인중개사 자문을 받아 중대한 오류와 평가 확정 여부를 작성했다는 사용자 확인에 따라 기존 14개 점수를 확정된 Before 정성 기준선으로 기록한다. 항목별 가중 합산이나 다른 지표와의 종합점수는 만들지 않는다. 점수·검토 의견·보류는 보존하며 After에 동일 기준을 적용한다.

## 2026-10-19: 단계 3A는 분석과 재현으로 제한
노트북에서 기존 기록을 읽고 외부 모델/검색만 모의화해 실제 그래프·서비스 함수의 연결 계약을 검증했다. 새로운 추적 프레임워크나 공통 모듈을 만들지 않는다. 노드 변경분과 누적 상태를 구분하며 과거 중간 상태를 추정 복원하지 않는다. 확인된 서비스 결함 6개와 설계 한계 3개를 답변 품질 원인 확정과 분리한다. 실제 검색 본문 전달 65/65는 문자 일치 확인이며 Faithfulness나 Correctness가 아니다. 수정·GPU 실행·Git 반영은 각각 후속 승인 대상으로 유지한다. 재현 결과와 실패·참고 자료·수정 통과 기준은 07_langgraph_flow.ipynb에 모았다.

## 2026-10-19: 부분 재현과 전체 그래프 감사를 구분
사용자가 요청한 전체 감사는 활성 노드 전부를 기준으로 한다. 기록이 없는 노드는 완료 처리하지 않고 필요한 실제 기록을 수집한다. 모의 연결 검증은 실제 검색/생성 품질의 대체물이 아니다. 노드별 코드·모의·실제 확인 상태를 07에서 관리하며 기존 Before와 새 node_audit_not_before 실행을 분리한다. 실제 검색 후보는 정답 조문 이름 일치만으로 관련도/판본 점수를 확정하지 않는다. 유료 실행·중지는 신규 시간/비용 승인 이후 진행한다.

## 2026-10-20: 실제 노드 기록에 근거한 최소 수정 우선
